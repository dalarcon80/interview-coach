# R1.1 Design — Dual-Mode UI Integration for `src/app/page.tsx`

> Task: `reintegrate_coach_components_into_active_ui`

## 1. Overview

The active web UI at [`src/app/page.tsx`](src/app/page.tsx) is currently a realtime-only dev preview. Five orphaned coaching components exist in [`src/components/coach/`](src/components/coach/) but are not wired into the page.

This design adds a **Preparation Mode** alongside the existing **Live Mode** behind a top-level mode switcher, while keeping the Architecture and Backend Status tabs intact.

### Design principles

- Modify, do not rewrite, the existing page.
- Do not break the existing realtime components.
- Do not change the backend API.
- Minimize changes to coaching component implementations.
- Desktop-first, clean layout.

## 2. Mode Switcher

### Placement

A new `Tabs` component is inserted **above** the existing `Session / Architecture / Backend Status` tabs, inside the `<main>` element, immediately after the status summary cards.

### Implementation

```

```

Use the existing [`Tabs`](src/components/ui/tabs.tsx) / `TabsList` / `TabsTrigger` / `TabsContent` from shadcn/ui.

The existing three-tab block — Session, Architecture, Backend Status — moves **inside** the `live` TabsContent, preserving its current behavior exactly.

## 6. Coaching Components → Backend API Wiring

### QuestionInput → `/api/coach/suggest`

[`QuestionInput`](src/components/coach/QuestionInput.tsx:59) already calls `fetch('/api/coach/suggest', ...)` internally at line 65. It sends:

```json
{
  "questionText": "...",
  "sessionId": null,
  "style": "mixed"
}
```

**Problem**: It does not send `candidate` or `company` context. The Next.js route at [`src/app/api/coach/suggest/route.ts`](src/app/api/coach/suggest/route.ts:23) accepts `candidate`, `company`, `cvFullText`, and `roleRequirements` fields and forwards them to the backend.

The backend at [`python-core/api/server.py:167`](python-core/api/server.py:167) accepts `candidate` as an object with `name`, `summary`, `achievements` fields, and `company` as an object with `companyName`, `roleTitle`, `jobDescription` fields.

**Required minimal change to QuestionInput** — see §7.

### SuggestionDisplay

[`SuggestionDisplay`](src/components/coach/SuggestionDisplay.tsx:53) is a pure display component. It receives `suggestion` and `question` as props. No API calls. No changes needed.

### StyleSelector

[`StyleSelector`](src/components/coach/StyleSelector.tsx:74) is a pure UI component. Receives `selectedStyle` and `onStyleChange`. No changes needed.

### CandidateProfileForm / CompanyInfoForm

Both are form components that call `onSave` with their data. No direct API calls. No changes needed beyond exporting their interfaces — see §7.

### 7b. Pass context to QuestionInput API call

**File**: [`src/components/coach/QuestionInput.tsx`](src/components/coach/QuestionInput.tsx:29)

Add optional `candidate` and `company` props:

```diff
  interface QuestionInputProps {
    sessionId: string | null;
    selectedStyle: ResponseStyle;
    onSuggestion: (suggestion: Suggestion) => void;
    onClear: () => void;
    isProcessing: boolean;
    setIsProcessing: (value: boolean) => void;
+   candidate?: { name: string; summary?: string; achievements?: string[] } | null;
+   company?: { companyName: string; roleTitle?: string; jobDescription?: string } | null;
  }
```

Update the fetch body at [`QuestionInput.tsx:68`](src/components/coach/QuestionInput.tsx:68):

```diff
  body: JSON.stringify({
    questionText: question,
    sessionId,
    style: selectedStyle,
+   candidate: candidate || undefined,
+   company: company || undefined,
  }),
```

This is the **only behavioral change** to a coaching component. It is additive and backward-compatible — the new props are optional.

### 7c. Track question text for SuggestionDisplay

The page needs to know the question text that produced the suggestion. Two options:

**Option A** — Extend `onSuggestion` callback to also pass the question text. This requires changing the callback signature.

**Option B** — Add an `onQuestionSubmit` callback prop to `QuestionInput` that fires with the question text when submitted.

**Recommended: Option B** — it is less invasive:

```diff
  interface QuestionInputProps {
    ...
+   onQuestionSubmit?: (question: string) => void;
  }
```

At [`QuestionInput.tsx:77`](src/components/coach/QuestionInput.tsx:77), after `onSuggestion(data.suggestion)`:

```diff
  if (data.success) {
    onSuggestion(data.suggestion);
+   onQuestionSubmit?.(question);
    ...
  }
```

Then in the page:

```tsx
<QuestionInput
  ...
  onQuestionSubmit={(q) => setPrepQuestion(q)}
/>
```

## 9. Hardcoded Defaults Removal

The current [`sessionConfig`](src/app/page.tsx:149) has:

```tsx
company_name: 'Target Company',
role_title: 'Senior Engineer',
```

These must be replaced with values derived from `companyInfo` state:

```tsx
const sessionConfig: SessionConfig = useMemo(() => ({
  company_name: companyInfo?.companyName || '',
  role_title: companyInfo?.positionTitle || '',
  response_style: responseStyle,
  language_preference: 'auto',
}), [companyInfo, responseStyle]);
```

This ensures Live Mode uses whatever the user entered in Preparation Mode, and defaults to empty strings rather than fake placeholders.
